
# Documentation Review Checklist

## Purpose

Use this checklist to review documentation before
approving a pull request.

The same quality standards apply to AI-generated
and manually written documentation.

## 1. Source Verification

- [ ] The document is based on approved source material.
- [ ] API operations match the OpenAPI specification.
- [ ] Request parameters and responses are accurate.
- [ ] Proposed features are clearly identified.
- [ ] Unsupported technical statements have been removed.
- [ ] Missing information is identified for verification.

## 2. Content Quality

- [ ] The purpose of the feature is explained clearly.
- [ ] Instructions follow a logical sequence.
- [ ] Examples are accurate and relevant.
- [ ] Terminology is consistent.
- [ ] Grammar, punctuation, and sentence structure
      have been reviewed.
- [ ] The document does not contain unnecessary
      promotional language or em dashes.

## 3. Technical Validation

- [ ] Code examples have been tested where applicable.
- [ ] API examples match the specification.
- [ ] Links have been checked.
- [ ] The documentation build completes successfully.
- [ ] Automated quality checks pass.
- [ ] Documentation drift checks pass.

## 4. AI Draft Review

Complete this section when AI was used to prepare
or update the documentation.

- [ ] The source documents are recorded.
- [ ] The AI model and drafting rules are identified.
- [ ] Unsupported claims have been reviewed.
- [ ] Known model errors have been corrected.
- [ ] Human review has been completed.

## 5. Publication Approval

- [ ] The document is ready for its intended audience.
- [ ] Required technical reviews are complete.
- [ ] All blocking issues have been resolved.
- [ ] The pull request has been approved.
- [ ] The documentation is ready to merge.
